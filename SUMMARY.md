# Git #3. Работа в команде — шпаргалка

## Ветка (branch)
- Указатель на последний коммит.
- `git switch -c feature/…` — создать и перейти.
- `git branch` — список, * — текущая.

## Слияние (merge)
- Стоим в main → `git merge feature/…`.
- Нет нового в main — перемотка.
- Иначе — коммит слияния.

## Конфликт (conflict)
- Обе ветки правили одну строку.
- Маркеры: >>>>>>.
- Выбрать, удалить маркеры, add, commit.

## Pull Request (PR)
- push ветки → Compare & pull request.
- Ревью напарника.
- Merge → все делают pull.

## Уборка (cleanup)
- `git branch -d` — удалить слитую.
- `git push origin --delete …` — на GitHub.
- -d не удалит неслитую.

## Правила команды (teamwork)
- Задача — своя ветка.
- В main — через PR.
- Сначала pull, потом push; без --force.

## Исключения и ловушки
1. merge вливает указанную ветку в ТЕКУЩУЮ.
2. Пока работа в ветке, в main её нет — это нормально.
3. Маркеры конфликта — не код: удалить все три.
4. После решения конфликта: add и commit, иначе слияние не завершено.
5. Новую ветку первый раз пушим с -u и её именем.
6. git push --force стирает чужую работу.
7. branch -d не удалит неслитую ветку — и правильно.
8. После слияния PR все делают git pull в main.
9. Конфликт возникает только при правках одних и тех же строк.
10. Перед новой веткой — switch main и pull: стартуем со свежего.
